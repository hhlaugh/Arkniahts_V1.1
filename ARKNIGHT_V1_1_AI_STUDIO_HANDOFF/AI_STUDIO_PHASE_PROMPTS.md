# AI Studio分阶段执行提示词

使用方式：完成 `AI_STUDIO_EXECUTION_PROMPT.md` 的项目导入与阶段0架构审计后，再按顺序将以下提示词逐项发给 Google AI Studio Build 代理。每个阶段完成后先检查代码变更、预览和测试结果，再继续下一阶段。

---

## 阶段0：架构审计（首次导入后使用）

```text
请严格按 AI_STUDIO_EXECUTION_PROMPT.md 执行阶段0。只审计，不修改代码。读取 V1.1 规则规格、未决事项、108张卡池、关键词字典和棋盘schema；对照当前项目的真实代码路径，输出模块现状、差异表、受影响文件、数据映射风险、分阶段实施计划和测试计划。不得根据 README 推测代码已经实现；不得擅自决定 OPEN_DECISIONS 中的事项。报告完成后停止，等待我确认。
```

## 阶段1：棋盘与空间模型

```text
根据阶段0审计报告和 spec/V1_1_IMPLEMENTATION_SPEC.md，实施V1.1棋盘/空间系统。先用不超过10条列出本阶段将修改的文件和迁移方案，随后实施。
要求：经典3路且每路前/后排各1格；自定义1–5路，每路前/后排最多3格；每路独立显示F1-F3/R1-R3；内部用(laneOrder,rowOrder,slotIndex)稳定排序；只将直接左右相邻路线视为相邻；默认禁止跨路移动；干员、设施、召唤物占格，战术/装备不占格。不要假设路线/格子固定数组长度。未决空路线/空排约束按原实现保留并报告。更新BoardProfile序列化和相关UI。新增测试覆盖经典3路、自定义1/3/5路、非对称布局、格子上限和相邻边界。完成后报告实际通过的测试及未完成项。
```

## 阶段2：攻击范围、索敌和伤害管线

```text
实施V1.1攻击与目标系统。先报告本阶段影响文件，再修改。范围解析必须与棋盘数据解耦；卡牌规则固定，不因棋盘变宽而自动增强；同路及相邻路线只覆盖直接左右邻路。普通攻击优先级为嘲讽 > 玩家集火目标指令 > 单位自身索敌；任何优先级均不扩大合法范围，不合法时回退。设施和召唤物按位置、阵营与卡牌目标文字参与候选。伤害顺序为攻击力/持续修正 > 当前攻击【集火】 > 【脆弱】 > 【掩护】 > 护盾 > HP > 伤害后事件；法术攻击无视掩护但仍受护盾。记录直接伤害来源。对攻击队列快照、范围目标快照等未决细节先核验原实现，不要凭常见卡牌游戏经验改写。增加目标优先级、边界路线、设施目标、召唤物目标和伤害管线测试。
```

## 阶段3：CP资源和费用适配

```text
实施V1.1 CP与费用系统。每位玩家独立计数自己的回合：1-6回合基础CP为3、4、5、6、7、8，之后保持8；己方回合开始重置当前CP为基础值，回合结束清零；当回合CP获取上限为min(10,基础CP+2)；补给/击杀回费无限触发但不得突破当回合上限；折扣叠加，最低费用0；单卡费用不得超过8。将108张卡池运行费用映射到command_cost_cp，必须以MASTER表为主、50列ENGINE表为兼容来源，保留card_id和其他字段。维护失败视为击倒，进入弃牌，不回手、不退款、不进入再部署冷却；普通主动撤离仍可用但不退款。非己方回合CP收益按OPEN_DECISIONS核验，不得自行建立跨回合资源银行。增加双方先后手回合计数、重置、清零、上限、折扣、维护和撤离测试。
```

## 阶段4：设施、装备、召唤物及卡牌生命周期

```text
实施V1.1场上实体生命周期。设施统一3 HP、占格、可被摧毁，按所在格位置参与普通攻击目标优先级；失效暂停全部效果，失效期间持续时间是否继续计数按OPEN_DECISIONS核验。装备卡成功使用后弃牌、不占格；目标单位最多一个装备效果包，新包覆盖旧包；已结算即时结果不回滚。召唤物占格，在场时按普通单位待遇参与合法友方/敌方效果；主动回收视为摧毁，触发摧毁事件，不回手、不退款、不计敌方击杀回费；召唤来源离场时关联召唤物按规则处理。不要擅自增加召唤物回收CP成本。维护失败和召唤物主动回收必须使用不同事件原因。增加覆盖、摧毁、释放格位、目标合法性和来源记录测试。
```

## 阶段5：卡池与关键词数据接入

```text
接入V1.1卡池与关键词字典。先比较项目现有schema与MASTER 60列/ENGINE 50列差异，明确每个字段映射，不得直接覆盖旧文件或静默丢字段。保留108个card_id；费用以MASTER的command_cost_cp为准；v3_3_original_cost_cp仅供审计。校验所有JSON、效果操作符、设施3HP、占格属性和装备/战术非占格。对引擎不支持的操作符逐个列出并实现通用操作，或明确记录为未实现；绝不能只显示卡牌文字而实际不执行。为新旧数据建立迁移/回滚方案，更新卡牌展示和收藏/牌组/抽卡相关读取路径。完成后输出字段映射表及数据验证报告。
```

## 阶段6：AI/机器人、UI、存档与回放适配

```text
适配AI/机器人、UI、存档和回放。AI必须使用与玩家相同的BoardProfile、合法动作、范围解析、目标选择和伤害规则；不得硬编码3路或每排一格。UI支持经典/自定义棋盘、配置选择、F/R格子标签、合法部署/移动、主动撤离、召唤物主动回收、设施和装备效果展示。存档/回放保存BoardProfile、实体稳定ID、玩家自己的回合序号、CP状态、随机种子和必要事件记录；旧存档提供兼容迁移或安全提示，不静默损坏。保持现有交互风格，避免无关UI重做。完成后分别跑经典3路和自定义5路机器人对局。
```
