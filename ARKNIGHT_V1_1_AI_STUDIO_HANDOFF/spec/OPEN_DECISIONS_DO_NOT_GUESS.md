# V1.1 待确认事项（开发代理不得擅自定案）

本文件只列出会显著改变玩法且用户尚未作最终选择的项目。开发代理应优先核验当前引擎行为；若无现成行为，则保留接口/配置并在实施报告中列出，不得自行编造数值或流程。

| 编号 | 事项 | 当前处理要求 |
|---|---|---|
| OQ-01 | 冻结是否阻止所有自身技能/受伤反应，以及冻结期间其他状态是否继续计时、能否被外部施加/解除 | 保留状态系统的独立控制标记；不自行扩大为“暂停目标一切状态”或“完全不受任何状态变化”。核验现行实现并报告差异。 |
| OQ-02 | 护盾数值上限 | 不将建议的10点写死。沿用当前引擎现行值；如果不存在上限，先暴露配置并报告。 |
| OQ-03 | 玩家集火指令的指定时点、每回合可否更改 | 实现“嘲讽 > 集火目标 > 单位自身索敌”的优先级；设置时点和更改限制沿用现有界面/规则，若无实现则留待确认。 |
| OQ-04 | 设施失效期间持续时间是否继续计数 | 失效必须暂停全部设施效果；持续时间计数方式先核验现行实现，不自行决定。 |
| OQ-05 | 自定义模式能否创建整条空路线/前后排空位 | 支持路线数1–5、每排最多3格；具体最小格数限制先核验现有设置器。 |
| OQ-06 | 主动回收召唤物的CP/行动成本 | 必须提供主动回收入口；回收视为摧毁，不回手、不退款、不计敌方击杀。不得擅自添加CP消耗；如现有行动系统要求消耗，则报告现有成本机制。 |
| OQ-07 | 装备卡一次性和装备效果包持续时间 | 本实施稿按“装备卡结算后进弃牌堆，安装效果包持续到被覆盖或宿主离场”实施。若代码现有语义明显冲突，列明后等待确认；不可把装备卡实体放在棋盘。 |
| OQ-08 | 非己方回合触发的CP获得事件如何入账 | 逐回合重置资源池已确定为本次提案；核验是否会在非所有者CP窗口触发击杀回费。不要擅自做跨回合银行或丢弃处理。 |
| OQ-09 | 【破片齐射】、【全线压制】等范围卡在大棋盘的固定目标上限 | 费用说明建议最多6个目标，但尚未确认且CSV卡面未写入；不擅自新增6目标上限。实现通用targetLimit能力并报告实际受影响卡。 |
| OQ-10 | 战斗队列快照与位移后顺序 | 稳定排序使用路线→前排/后排→排内位置；队列是开战快照还是动态处理，优先核验当前引擎，不改变既有时序除非为支持新棋盘必须修改。 |
| OQ-11 | 普通主动撤离后的再部署冷却/卡牌区域 | 只冻结CP退款；其余沿用当前程序规则，不要把普通撤离改成击倒或弃牌。 |
| OQ-12 | 设施具体持续时间触发先后 | 所有设施3 HP已确定；失效暂停效果已确定；效果触发与回合寿命扣减顺序沿用当前实现，必要时列出建议供用户确认。 |
